# uno-rl：UNOの強化学習（情報工学特論 GW 9班）

> このブランチ（`experiment/numbers-0-9-no-limit`）は実験用で，数字カードを0〜9にし，手札の上限をなくしている．`main` は数字1・2で手札12枚が上限である．

簡略版UNOの環境と，5種類の学習手法（Sarsa，バケツリレー，Profit Sharing，モンテカルロ法，Q学習）を実装したものである．学習済みのモデル70個をブラウザで選び，ランダムとルールベースの相手と対戦する様子を見られる．

## すぐに見る

`uno_player.html` をブラウザ（Chrome または Edge）で開く．インストールは要らない．

- 学習手法，学習した試合数（10,000〜1,000,000），学習相手，対戦相手を選ぶと，そのモデルが新しい配札で試合を始める．
- テーブルのカードの動き，手札の各カードの Q，選べる手ごとの Q の棒，選んだ手の Q の推移が表示される．
- 選択欄の下に，そのモデルの学習直後の勝率（各2,000試合）が出る．
- 「このモデルと対戦する」を押すと，あなたがカードを選んで選んだモデルと対戦できる．手札の各カードにそのモデルの Q が出るので，モデルがコーチだったらどの手を勧めるかが分かる．出せるカードをクリックし，山札をクリックして引き，+4 では色を選ぶ．「戻る」（← キー）で直前の自分の手を取り消せる．
- 右上の「Language / 言語」で英語と日本語を切り替えられる（ブラウザの言語に合わせて最初の言語が決まり，選んだ言語は次回も使われる）．

## 必要なもの

- Python 3.10 以降（標準ライブラリだけで動く）
- Node.js（`check_js.py` と `web/model_test.js` を使うときだけ）

## 使い方

```bash
python test_env.py                       # 環境の確認．ALL OK と出ること（約1分）
python run.py --algo sarsa --episodes 200000 --opp rule --seed 0   # 手法を1つだけ学習して評価
python run.py --algo all --episodes 100000 --opp random --jobs 5   # 5手法を並列に学習
python train_all.py                      # 学習済みモデル70個を作る（約3分，途中から再開できる）
python build_page.py                     # models/ から uno_player.html を作る
python watch.py --algo sarsa --episodes 20000                      # 手ごとの Q を文字で見る
python watch.py --algo sarsa --episodes 200000 --html              # 1試合のアニメーションを書き出す
python analyze.py --vs rule              # 行動の傾向を集計する（results/*_q.json を使う）
python check_js.py                       # ページのゲームが Python と一致するか確かめる（Node が要る）
```

`run.py` の主なオプションは次のとおりである．

| オプション | 意味 |
| --- | --- |
| `--algo` | `sarsa`，`bucket_brigade`，`profit_sharing`，`monte_carlo`，`qlearning`，`all` |
| `--opp` | `random`，`rule`，`random+rule`（対ランダムで学習したあと，同じエージェントで対ルールベース） |
| `--episodes` | 学習する試合数（`random+rule` のときは各段階の試合数） |
| `--rule キー=値` | ルールを変える（何度でも指定できる）．例：`--rule hand_limit=0` |

## ゲームのルール

`game.py` の `Rules` の既定値が現在のルールである．

| 項目 | 内容 |
| --- | --- |
| 人数 | 2人（エージェント 対 相手） |
| 山札 | 50枚：2色 ×（数字0を1枚，数字1〜9・スキップ・+2 を各2枚）＋ +4 を4枚 |
| 初期手札 | 7枚 |
| 出せるカード | 場札と同じ色，または同じ数字・記号．+4 はいつでも出せる |
| ドロー | 出せるカードがあっても1枚引ける．引いたカードは出すかパスを選ぶ |
| 重ね出し | +2に+2，+4に+4，+2に+4 |
| 勝敗 | 先に手札を空にした方が勝ち．手札の上限はない |
| 引き分け | 500手番で決着しなければ引き分け |

色の指定と出すカードの選択は固定ルールにせず，学習で決める．ルールを変えると全モデルを学習し直す必要がある．

## 強化学習の定式化

エージェントは，手札の枚数，場札の色の順位，ペナルティ待ち枚数，出せるカードの種類などの抜き出した状態を観測する（状態数は最大5,120）．行動は「カードの種類 × 色順位」とドローとパスの10種類である．報酬は勝ちが +1，負けが −1，それ以外は 0 であり，終了時にだけ与える．定義は `env.py` にある．

## 学習手法

| 手法 | ファイル | 更新のタイミング |
| --- | --- | --- |
| Sarsa | `algos/sarsa.py` | 1ステップごと（オンポリシー） |
| バケツリレー | `algos/bucket_brigade.py` | 1ステップごと |
| Profit Sharing | `algos/profit_sharing.py` | エピソード終了時 |
| モンテカルロ法 | `algos/monte_carlo.py` | エピソード終了時 |
| Q学習 | `algos/qlearning.py` | 1ステップごと（オフポリシー）．おまけ |

行動の選択は全手法でボルツマン選択（温度は 1.0 から 0.05 まで減らす）であり，評価は学習を止めたグリーディ方策で行う．自分の手法を書き直すときは，`algos/<手法>.py` に `HP` と `episode(ag, env)` を用意すればよい．

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `game.py` | UNOのゲーム本体とルール `Rules` |
| `env.py` | 強化学習の環境（状態・行動・報酬） |
| `opponents.py` | ランダムとルールベースの相手 |
| `algos/` | 学習手法とその共通部分 |
| `run.py` | 学習・評価・結果の保存 |
| `train_all.py` | 学習済みモデル70個を作る |
| `models/` | 学習済みモデル（5手法 × 学習相手2種 × 7種類の試合数） |
| `build_page.py` | モデルとゲームを1つのHTMLにまとめる |
| `uno_player.html` | モデルを選んで対戦を見るページ |
| `web/engine.js` | ページ用のゲーム．Python のゲームを JavaScript に移したもの |
| `check_js.py`，`web/` | JavaScript が Python と同じ動きをするかの確認 |
| `watch.py`，`analyze.py` | 学習の様子の表示と行動の集計 |
| `test_env.py` | 環境の確認 |

## 注意

- ページは2人対戦で，現在の既定のルールだけに対応している．
- `game.py`，`env.py`，`opponents.py` を変えたら，`web/engine.js` にも同じ変更を入れ，`python check_js.py` で確かめ，`models/` を作り直してから `python build_page.py` を実行する．
- 付属のモデルは `algos/` の参考実装で学習したものであり，勝率は1回の学習の結果である．
